# WLLPR — Procedural Wallpaper Generator

#### Description:

WLLPR is a web application that generates abstract landscape wallpapers procedurally — every image is drawn from scratch with code on an HTML5 canvas, not stored as a file. From a single numeric "seed" the app produces layered scenes such as rolling hills with pine trees, flowing waves, sand dunes, jagged mountains, concentric arcs, and free-form desert scribbles. Each scene can be recolored across 13 hand-tuned palettes, flipped between light and dark variants, previewed with a live macOS-style clock overlay, and exported as a high-resolution PNG for either a 4K desktop (3840×2160) or an iPhone screen (1290×2796). The app is written in vanilla JavaScript (ES modules), HTML, and CSS, with no front-end framework, and is deployed as a static site on GitHub Pages.

I used Dia AI to help structure the front-end layout and to develop the pine-tree and flowing-hills generator; all generated code was reviewed and adapted by me, and these uses are also cited in the relevant source files.

The project is organized as a small multi-page site. `index.html` is the home page: it shows a large "featured" wallpaper hero and a series of horizontally-scrolling carousels, one per pattern type. `create/index.html` is the interactive editor, and `wallpaper/index.html` is a full-screen detail view for a single wallpaper. Shared styling lives in `styles.css`, and a light/dark theme choice is persisted in `localStorage` so the site remembers the user's preference between visits.

All of the actual drawing logic lives in `js/engine.js`, which is the heart of the project. It defines the palettes and pattern list and implements a small procedural-graphics toolkit: a `mulberry32` seeded random-number generator so that the same seed always reproduces the exact same image, a 1-D value-noise function smoothed with `fbm` (fractional Brownian motion) to create natural-looking ridgelines, and a `lerpColor` helper that interpolates between palette stops to produce smooth gradients. On top of these primitives sit six independent draw functions — `drawFlowingHills`, `drawSmoothWave`, `drawSandDunes`, `drawMountains`, `drawConcentricArcs`, and `drawDesertDunes` — each of which layers translucent shapes to build depth, with the hills routine even scattering procedurally-generated pine trees along each ridge. `drawClockOverlay` renders a Portuguese-language date and time on top, and `exportWallpaper` re-renders the scene at full export resolution onto an off-screen canvas and saves it as a PNG. The engine exposes everything it needs through ES-module exports so the other files can reuse it.

`js/wallpapers.js` is the data layer. Rather than storing image files, it stores a list of roughly 168 wallpaper "recipes" — each is just an object recording which pattern, palette, seed, and light/dark setting to use, plus an `id` and display name. Because rendering is deterministic, these tiny objects are enough to reproduce every wallpaper on demand, which keeps the whole gallery essentially weightless. It also groups patterns into sections for the home page and exposes helper functions `getWallpaper(id)` and `getFeatured()`.

`js/home.js` builds the home page by importing the wallpaper list and the engine, rendering each recipe onto a small canvas thumbnail, and assembling the featured hero plus one scrollable carousel per pattern section, wiring up the left/right scroll arrows. `js/detail.js` powers the full-screen view: it reads the wallpaper `id` from the URL query string, redraws that wallpaper at full size, fills in its metadata, and provides a download dropdown (desktop or mobile resolution). `js/create.js` drives the editor: it builds the clickable pattern grid and palette swatches, handles the dark/light toggle, has a "shuffle" button that picks a fresh random seed, and re-renders the desktop and mobile previews live on every change.

One design decision worth explaining is why wallpapers are stored as recipes instead of image files. Storing 168 full-resolution PNGs would make the repository enormous and slow to load. Because the generator is deterministic, saving only the four parameters that define each image lets the browser regenerate any wallpaper instantly at whatever resolution is needed, whether that is a 320-pixel thumbnail or a 4K export. Another decision was to keep everything in vanilla JavaScript with no framework: the project is small enough that ES modules and direct DOM manipulation are clearer than adding a build step, and it deploys to GitHub Pages with no compilation. A `.nojekyll` file is included so GitHub Pages serves the `js/` folder correctly.

The project also has a companion desktop build (using Tauri) on a separate branch that can set the wallpaper directly on macOS, but this web version is the primary, self-contained submission.
